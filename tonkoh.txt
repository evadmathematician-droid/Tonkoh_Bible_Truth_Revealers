1. OVERVIEW
-------------------------------------------------------------------------------
Tonkoh is a Flutter app for the Tonkoh Bible Truth Revealers community. It
combines three things in one app:

  * A gospel / sermon AUDIO FEED (upload, admin approval, playback,
    download, sharing)
  * PRIVATE CHAT between members (text, photos, video, voice notes,
    reactions, unread counts)
  * VOICE AND VIDEO CALLS between members (WebRTC, with native Android
    call screens and push-based ringing)

Android is the main target. The project also has iOS, web, macOS, Windows
and Linux folders, but calls on Android go through a native Kotlin layer
that the other platforms don't have.

5. MAIN FEATURES
-------------------------------------------------------------------------------
5.1 Sign-in and profile
  - Firebase anonymous sign-in; the user's record is stored under
    users/{phone}. A random per-install device id marks which device owns
    the account (activeDeviceId). If another device takes over, AuthGate
    signs the old one out.
  - Profile setup: name, phone (international picker), country, photo.

5.2 Account migration (moving to a new phone)
  - Handled by the Worker's /migration-verify endpoint.
  - If the old device has been offline > 5 minutes, the transfer happens
    directly. If it was online recently, the user must name at least one
    real previous chat partner.
  - Lockout after repeated failures: 1 hour, 24 hours, then 7 days.
  - Every transfer is written to migrationLog; both devices get an
    "Account moved" push.
  - Old message history does NOT transfer (messages live only in each
    device's local database).

5.3 Audio feed
  - Members upload sermons/audio (via Cloudinary); an admin approves or
    rejects them (sermons/pending -> approved / rejected).
  - Background playback with media notification and lock-screen controls.
  - Download for offline use, sharing, replies.

5.4 Chat
  - One-to-one chats with text, images, video, voice notes, reactions.
  - Local SQLite stores for messages and read positions; RTDB userChats for
    the chat list and unread counts.
  - Contacts matched against phone book / SIM contacts.

5.5 Calls
  - Voice and video via WebRTC, TURN credentials from the Worker.
  - Android: native Telecom ConnectionService, full-screen incoming call
    activity, foreground services, OneSignal notification extension to wake
    the phone for a call.
  - Other platforms: Flutter call screens driven by an RTDB listener.
  - Missed-call tracking and call-reliability tips (battery optimisation).

5.6 Admin
  - Admin area unlocked with a PIN (stored in the app as a SHA-256 hash).
  - Feedback inbox and audio approval queue.

5.7 Force update and maintenance mode
  - Remote Config keys: min_version_code, latest_version_code,
    force_update, update_message, playstore_url, apk_url,
    maintenance_mode, maintenance_message.
  - Compares integer version codes; the last policy is cached so it still
    applies offline. Uses Play in-app IMMEDIATE update, falling back to the
    Play Store / APK link.
  - The gate sits above the navigator, so outdated installs can't reach any
    screen, including call screens opened from notifications.

8. ISSUES AND RISKS FOUND
-------------------------------------------------------------------------------
HIGH
  1. Release build is signed with the DEBUG key
     (android/app/build.gradle.kts: signingConfig = debug). Google Play
     will reject it, and debug keys are not unique to you. Set up a real
     upload keystore before publishing.

  2. Shared Worker secret is hard-coded in the app as
     "test-relay-secret-123" in 6 places (call_initiator, migration_service,
     onesignal_push, auth_manager, private_chat_push). Anyone who unpacks
     the APK can call /send-push, /send-call-push and /migration-verify.
     At minimum, replace the test value; better, have the Worker check a
     Firebase ID token instead of a shared secret.

  3. No phone-number verification (no SMS OTP). Accounts are keyed by the
     phone number the user types, on top of anonymous auth. Security relies
     on the device-ownership check, the migration rules and the database
     rules, and the full database rules are NOT in this repository (only
     cloudflare/firebase_rules_migration.json), so they couldn't be checked.

MEDIUM
  4. Admin PIN check runs only on the device. The SHA-256 hash of a short
     numeric PIN can be brute-forced offline in seconds. Admin rights
     should be enforced in the database rules (e.g. an admins list), not
     just in the UI.
  5. The Worker setup notes suggest a legacy Firebase DB secret (full admin
     access) as one option. Prefer the service-account token, which the
     current worker_full.js already uses.
  6. Unfinished items:
       - /message route is a "not yet ported" stub
       - TODO: audio-feed push notification (audio_feed_provider.dart:252)
       - TODO: own profile-photo cache update (auth_manager.dart:263)
       - lib/calls/ringback_manager.dart is an empty file

LOW / HOUSEKEEPING
  7. cloudflare/worker_full.txt duplicates worker_full.js (697 lines each).
     Keep one.
  8. android/build/reports/problems/problems-report.html (a build output)
     is committed. Add android/build/ to .gitignore.
  9. README.md is still the default Flutter template.
 10. Branch: work is on "master" while the main branch is "main".
 11. private_chat_screen.dart (1,450 lines) is large; splitting it would
     make it easier to maintain.
 12. Several comments refer to the old Kotlin app ("mirrors AuthManager.kt")
     that isn't in this repo.
